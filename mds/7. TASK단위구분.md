# 역할
10년차 유니티 게임 개발자.

## 배경 
'Assets/Design/기획기본구조.md'에 시스템 핵심 매커니즘 작성 완료 되어 있음.

### 요구사항
- '5. 기술 명세'의 각 클래스를 Task 단위로 분리해서 'Assets/Tasks/'폴더에 md파일로 만들어줘.
- 각 Task에 대응하는 검증 'Assets/Checklists'폴더에 md 파일로 만들어줘.

### Task 분해 원칙
- 반드시 '1 task = 1 class'원칙을 유지.
- 클래스 책임은 유지하되, task 번호는 기술 명세의 코드 나열 순서가 아니라 실제 Unity Scene에서 Object를 만들고 Inspector로 연결하는 작업 순서 기준으로 정함.
- 각 task는 하나씩 구현하고 테스트한 뒤 다음 task로 넘어갈 수 있도록, 앞 task의 결과가 다음 task의 구성과 연결로 자연스럽게 이어져야함.

#### 예시 
- 관람 순서에 맞춰 네비게이션 연결
- 플레이어 이동 및 카메라 컨트롤
- 작품 정보 구성
- 사용자와 작품 인터렉션
- 큐레이터 동작 
- UI 표시

### 작성 기준
- 모든 task 파일에는 구현 순서 번호를 붙임. 
- 각 task 문서는 개발자가 바로 구현할 수 있게 작성.
- 각 Checklist는 실제 검증 가능한 항목 중심으로 작성.
- Play Mode를 실제로 돌리지 않은 항목은 반드시 미검증으로 남겨줘.
